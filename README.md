# Lumasite single-lap capture (browser spike)

A mobile-web prototype that guides one slow lap of a room and shows a coverage ring
(12 slices × ceiling / walls / floor). It runs in iPhone Safari and Android Chrome with
no install. It's a feasibility spike: see [SPIKE.md](SPIKE.md) for the test protocol.

## Run it

```bash
npm install
npm run dev
```

Vite prints a `Network:` address such as `https://192.168.1.23:5173/`.

### Open it on a phone (same Wi-Fi)

Camera and motion sensors need HTTPS. The dev server uses a self-signed certificate
(`@vitejs/plugin-basic-ssl`), so each phone shows a warning the first time:

- **iPhone (Safari):** open the `https://…:5173` address, tap **Show Details →
  visit this website → Visit Website**.
- **Android (Chrome):** open the address, tap **Advanced → Proceed to … (unsafe)**.

The phone and the Mac must be on the same network. Some office or guest Wi-Fi
blocks device-to-device traffic; if so, use a tunnel.

### Or use a tunnel (no certificate warning, works off-LAN)

```bash
brew install cloudflared
```

```bash
HTTP=1 npm run dev
```

```bash
cloudflared tunnel --url http://localhost:5173
```

Open the `https://….trycloudflare.com` URL it prints on the phone. (`HTTP=1` turns
off the self-signed certificate because the tunnel provides TLS.) Vite may refuse the
tunnel's host name; if it does, add it to `server.allowedHosts` in `vite.config.ts`.

### Try it on a laptop: simulator

Open `/?sim=1`. The camera is replaced by a fake room and the motion sensors by a
scripted person. The panel on the right runs a whole lap ("Auto lap", or "Auto lap,
leave 2 gaps" to exercise the gap flow), shakes the camera (auto-pause) or dims the
room. Arrow keys turn and tilt. From the console:

```js
__sim.set({ pitch: 30, heading: 45 }); __sim.shake(true); await __sim.autoLap();
```

### Blue-dot variants

Four optional dot behaviours, all on by default (`config.guidance.dot`):

| Switch | What it does |
| --- | --- |
| edge arrow | When the target is off screen, the dot becomes an arrow at the edge, nudging the way to turn. |
| dwell fill | A green ring fills around the white circle during the 0.6 s hold. |
| smooth move | When the target changes, the dot glides there (350 ms) instead of jumping. |
| hold zone | A ring (12°) around the dot. The cell the dot points at only counts while the circle is inside it, so the dot no longer jumps away before you reach it. Cells passed on the way still count. |

Toggle them live in the simulator panel ("Blue dot"), or pick them in the URL, which
also works on a phone: `?dot=arrow,fill`, `?dot=all`, `?dot=none`. The active set is
logged in the `capture-start` event.

## Upload to Supabase

When "Room captured" appears, the phone uploads the recording and `session.json` to
the Supabase project and adds a row to `capture_sessions`. Testers can still use
**Download recording + log**. Without a key in `.env.local`, uploading is off and
nothing changes.

One-time setup:

1. In Supabase, open **SQL Editor**, paste [`supabase/setup.sql`](supabase/setup.sql)
   and run it. It creates a private `captures` bucket and the `capture_sessions` table.
   Phones can only add files and rows; they can't read, list or delete anything.
2. In **Project Settings → API Keys**, copy the anon (or publishable) key into
   `VITE_SUPABASE_ANON_KEY` in `.env.local`, then restart `npm run dev`.

To see what came in, use the dashboard (**Table Editor → capture_sessions**,
**Storage → captures**). Video is stored as `<session>/seg<N>/<seq>.part` chunks;
to get playable files:

```bash
SUPABASE_SERVICE_ROLE_KEY=your-secret-key node scripts/fetch-capture.mjs --list
```

```bash
SUPABASE_SERVICE_ROLE_KEY=your-secret-key node scripts/fetch-capture.mjs <session id>
```

That writes `captures/<id>/seg0.webm` (or `.mp4`), one per segment, plus `session.json`.
Keep the secret key in your shell, never in `.env.local`.

The free plan holds 1 GB of files, about 30 minutes of recording at 4 Mbps.

## Tests

```bash
npm test
```

Vitest covers the pure modules in `src/core`: orientation maths, frame quality (with
PNG fixtures in `src/core/__fixtures__`, regenerated by `npm run fixtures`),
the coverage dwell rule, lap and gap guidance, the session log, wording and
in-app-browser detection.

## Tuning

Every threshold is in [`src/config.ts`](src/config.ts): band pitch limits, smoothing,
dwell time, blur/brightness limits, rotation limits, auto-pause, field of view used to
place the dot, progress words, codecs, timeslice, bitrate and log rate. UI code reads
from it and never hard-codes a threshold.

## Debug overlay

Triple-tap the status pill ("Recording") to show live fps, quality sample rate,
pitch, heading (raw / unwrapped / progress / compass), rotation rate, blur,
brightness, the current cell, drift estimate, codec and bytes recorded. "save log
now" downloads the session log so far.

## How it's put together

```
src/config.ts         all thresholds
src/core/             pure TypeScript + unit tests (no DOM)
  orientation.ts      Euler angles → camera vector → pitch / heading, smoothing, unwrap, drift
  quality.ts          Laplacian-variance blur score and mean brightness
  coverage.ts         12×3 cells, dwell rule, skip, gaps, progress words
  lap.ts              walking direction, progress, lap complete
  guidance.ts         dot target and position, instruction and gap wording
  session-log.ts      the JSON log and its summary
  environment.ts      platform and in-app webview detection
  wording.ts          "One floor area was blocked…" sentences
src/platform/         thin browser adapters (permissions, sensors, MediaRecorder,
                      IndexedDB, quality worker, speech, upload stub)
src/capture/          CaptureController (runs a session outside React) and export
src/ui/               screens and capture overlay (ring, dot, sheets, debug)
src/dev/              ?sim=1 simulator
```

Notes:

- Pitch and heading come from the full rotation matrix of `alpha/beta/gamma` (the rear
  camera is the device's −Z axis), not from raw `beta`. The camera direction doesn't
  depend on screen rotation; `screen.orientation.angle` is used to orient the dot on
  screen and is logged.
- Coverage is advanced on every sensor reading, not on animation frames, so it keeps
  working if the UI frame rate drops.
- Each `MediaRecorder` chunk (2 s) is written to IndexedDB as an `ArrayBuffer` when it
  arrives. Every pause or interruption ends the current segment; Resume starts a new
  one. The download gives one video file per segment plus `session.json`.
- The camera is requested with `facingMode: "environment"` and an ideal 1920×1080
  (`config.camera`); the actual track size is logged.
- `src/platform/upload.ts` uploads to Supabase after "Room captured" (see below). Each
  2 s chunk is its own object, so a retry only re-sends what didn't land.
